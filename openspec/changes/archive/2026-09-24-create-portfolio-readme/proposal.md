## Why

The repository currently contains four detailed project briefs (`places-app.md`, `postulog.md`, `multimax-crm.md`, `odontosoft.md`) but no entry point. Anyone landing on the repo sees raw source notes instead of a curated portfolio. A single, well-structured README is needed to present the four projects and make the technical depth obvious at a glance.

## What Changes

- Create a root `README.md` as the portfolio entry point (GitHub profile/repo README), written in Spanish.
- Present the four projects as a consistent, scannable set of sections, each with: one-line pitch, role/context, stack summary, and a dedicated **Decisiones técnicas** highlights block.
- Add navigation (table of contents, badges) and a short "about me" / contact header.
- Include explicit, clearly-marked placeholders for what is added later:
  - repository links (currently unknown; must not be invented)
  - project screenshots/images
- Keep the four existing briefs as backing documentation and link to them as the detailed source, rather than duplicating all content.
- Establish reusable README conventions (heading hierarchy, project section template, badge style) so future projects are added consistently.

## Capabilities

### New Capabilities
- `portfolio-readme`: the required structure, content, and honesty/placeholder rules for the repository's portfolio README.

## Impact

- New file: `README.md` at the repository root.
- No runtime, API, dependency, or build impact (documentation-only change).
- Existing files `places-app.md`, `postulog.md`, `multimax-crm.md`, `odontosoft.md` remain and are referenced as detailed briefs.
- Unknown values (repo URLs, images) are represented as placeholders; nothing is fabricated.
